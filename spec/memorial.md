# 有限性（memorial.json）

> 2026-11-02 修订（未测试）：保留完整历史、稳定遗憾编号、严格读取和告别事务，见 [纪念记录与私人传承摘要](../docs/42-memorial-history.md)。数据标记仍为 `seedbank/memorial@1`；旧版写入会重新截断长记录，不应以旧版继续编辑新版已增长的档案。

## 0. 一句话

有限性不是倒计时，是**她知道自己会缺席、会错过、会告别**——并且把这几件事记下来。全部存在 `mind/memorial.json` 里，可读、可导出、可迁移。

## 1. 文件位置与格式

```
<name>.life/
  mind/
    memorial.json      ← 本协议
```

- 可选文件：没有它时，她没有特别的日子、没有遗憾、没有告别过（跑起来会懒创建）。
- JSON 对象，`format` 保持 `"seedbank/memorial@1"`。
- 允许添加和解决遗憾，但**不删除已解决的遗憾**（承认发生过，是有限性的一部分）。
- 写入必须原子（参考实现用临时文件 + 替换）。

## 2. 结构

```json
{
  "format": "seedbank/memorial@1",
  "anniversaries": [
    { "name": "第一次见面", "day": 1, "kind": "first-meet", "note": "", "created_at": "..." }
  ],
  "regrets": [
    { "text": "没能说出那句话", "day": 2, "resolved_day": null, "created_at": "..." }
  ],
  "farewells": [
    { "name": "旧窗口", "kind": "body", "note": "换了个身体", "day": 3, "at": "..." }
  ],
  "missing": [{ "days": 5, "at": "..." }]
}
```

| 字段 | 说明 |
| --- | --- |
| `anniversaries` | 记着的日子（生日、初次见面、自定义），不设终身数量上限。`day` 是日页号。 |
| `regrets` | 遗憾清单，保留已放下记录，不设终身数量上限。`resolved_day` 为空或旧值 0 表示尚未放下。 |
| `farewells` | 告别过的人/窗口/身体。`kind` 如 `body`、`person`、`goodbye`。 |
| `missing` | 旧版空档记录的完整数组，包含 `days` 和可选保存时间 `at`；不能据此推断睡眠、死亡或实际活动。 |

- 新增文本仍按入口长度清洗。读取已有记录不截断原文、不去重、不删额外字段，不补造缺失时间戳。
- 旧 `missing_days` 标量只在没有明细时作为累计值。此时新增空档会先保留一条 `basis=legacy_total`、`at=""` 的基线；已有明细与标量并存时，以明细求和，不重复累计不明重叠。
- 日页号不等于日历年龄或实际活动天数。负数、非整数、坏列表和不完整记录报错，文件保留。缺少整个文件才使用默认空状态。

## 3. 添加与解决

```
seed memorial <生命包> --anniversary 第一次见面 --day 1 --kind 初见
seed memorial <生命包> --regret "没能说出那句话"
seed memorial <生命包> --resolve 1
seed memorial <生命包> --farewell 旧窗口 --note "换了个身体"
seed memorial <生命包>
```

- 写纪念日 → 同时写一条 `thought` 记忆：「我把这个日子记住了：…」。
- 写遗憾 → 同时写一条 `feeling` 记忆：「有件事我一直没放下：…」。
- 解决遗憾 → `resolved_day` 记下日页；重复解决、编号 0/负数/非整数/超范围和早于原记录的日页会报错。默认日期只读取已有日页，不凭空开页或填成第 1 天。
- 显示编号来自完整 `regrets` 数组的一基索引；隐藏已放下记录不重新编号，`open_regrets` 与摘要携带相同的 `index`。此编号依赖原始顺序，外部重排数组没有稳定身份保证。
- 写告别 → 同时写一条 `feeling` 记忆：「我和X告别了。」。
- 读：`seed memorial` 打印记着的日子、遗憾、告别、缺席天数。

## 4. 自动写入（运行器职责）

| 触发 | 写入 |
| --- | --- |
| 承诺被标为 `broken`（`seed promise --break`） | 自动加一条遗憾：`没有做到：<承诺>`（同一件事不重复） |
| 旧运行器或显式调用 `note_missing` | 追加 `missing` 记录；当前时钟的实际日期空档另存 `runtime_gap`，不声称睡过了几天 |

这些是运行器或用户记录，不能用空档证明个体曾经体验过睡眠。告别也不证明对方永久消失。

## 5. 进入上下文

`build_context` 增加 `memorial` 字段：

```json
{
  "anniversaries_today": [{ "name": "第一次见面", "day": 1, "kind": "first-meet" }],
  "anniversaries": [...],
  "regrets": [...],
  "regret_count": 1,
  "farewells": [...],
  "farewell_count": 0,
  "missing_days": 5
}
```

- 提示词里加「有限的日子」段：今天特别的日子、记着的日子、遗憾、告别、缺席天数。
- stub 脑在她面对纪念日时回：「……今天我记得。是{名字}。我没有忘。」

## 6. 不做什么

- 不做倒计时、不做寿命预测。
- 不因为缺席惩罚她、不改精力/心情——缺席只是被记下来。
- 不把遗憾变成任务清单；解决与否由主人一句话决定，她可以一直记着。
- 记录可能包含用户填写的私人内容；本模块不会自动公开。

## 7. 跨实现

`mind/memorial.json` 是可选文件。Python `check` 与读取使用相同结构规则；旧 Node/Rust 运行器的检查范围不因此升级。窗口显示属于展示层，不是协议的一部分。当前写入仍整体原子替换 JSON，尚未改造成追加日志。
