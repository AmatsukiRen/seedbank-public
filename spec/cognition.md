## 0. 一句话

认知循环 = 她怎么把「发生过的事」变成「她成为的人」，以及反过来怎么用「她是谁」去理解新的事。
压缩只是其中的手段：写入时提炼，读取时选择。

## 1. 底层原则

- **生命层不可压缩。** `life/` 全量、只追加。她的一整天必须能被完整读一遍。
- **注意力可压缩。** 工作上下文和搜索索引可重建；`mind/` 中的记忆、经历与成长事件历史不能当作缓存丢弃。
- **遗忘要诚实。** 忘了就忘了，不假装记得，也不编造细节。
- **可复现。** seed + prompt 版本 + 模型版本必须留档。
- **脑可换，她不可换。** 换脑必须过人格回归测试（1.1）。

## 2. 三个时间尺度

| 尺度 | 发生了什么 | 写回哪里 |
|---|---|---|
| 每次对话 | 回应、提炼 | `life/` 当天（`## 对话`）、`mind/memories.jsonl` |
| 每天 | 日记、更新自我模型、收尾当天 | `life/` 当天（`## 今天`、心情） |
| 每月 | 整合、遗忘、重写信念（1.1） | `mind/memories.jsonl`、`mind/beliefs.md` |

## 3. 记忆四层

| 层 | 存在哪 | 存什么 | 寿命 |
|---|---|---|---|
| 工作记忆 | 上下文窗口 | 本次对话原文 | 一次运行 |
| 情景记忆 | `mind/memories.jsonl` + `mind/experiences.jsonl` | 提炼与原始事件分别留档，带来源、时间和修订关系 | 历史保留，读取可限制 |
| 语义记忆 | `mind/development.jsonl` | 信念、偏好、目标及其依据 | 追加修订 |
| 自我 | 出生身份 + 有依据的成长状态 | 她是谁、习惯、原则 | 随经历修订；旧 self.md/beliefs.md 仅为待核实历史 |
| 展示层 | `life/*.md` | 一天一篇的可读日记 | 永久（只追加） |

## 4. 一天的格式

```markdown
# 第 0002 天 · 2026-10-31

## 对话

**主人**：今天怎么样？

**小蓝**：光有点淡。我数了一会儿泡。

## 感知

- 光：光很亮，是暖的。光从左边来。（64×48 的图，指纹 e0d4c6a5）
- 声：有声音，不大，一阵一阵的。（指纹 3641717c）

## 见闻

- 海边的灯塔亮了。（来源：群聊）

## 今天

（收尾时由日循环写入：她今天想了什么。）

---

*安静。*
```

- **一天由「对话」「感知」「见闻」「今天」四段组成**（感知、见闻可缺省）。有 `## 今天` = 这一天已经结束；没有 = 这一天还开着。
- 第 1 天在孵化时就已经闭合（genesis 就是那天的「今天」），并自带一次出生光感（`## 感知`）。
- 同一天的对话与感知只能追加在 `## 今天` 之前。日循环一旦收尾，这一天就不能再改。
- 对话格式：`**名字**：内容`；空行分隔每轮。感知格式：`- 光：…` / `- 声：…` / `- 主人：…`。
- **见闻格式：`- 内容（来源：谁/哪里）`**（1.10）。这是她读到的，不是她经历的：每行都必须带来源；原文不落盘，只留摘要。

### 4.1 见闻（1.10：她读到的）

- 入口：`seed feed <生命包> [--source 来源] [--file 文件] [--max N]`；载体也可以把群聊的公共摘要交进来。
- 一次最多 12 条（`NEWS_MAX_ITEMS`），单条最多 200 字；同一批里去重，不同天不去重。
- 见闻保留原始记录；提炼受每轮记忆配额约束，未提炼的原始内容可经档案检索找回。
- 记忆条目：`kind: hearsay`、`importance: 0.3`、`tags: ["见闻", 来源]`、`runner: "feed-v1"`；和所有记忆一样会被遗忘、降权。
- **不写进 `friends/`，不算 `conversation`，不改变她对某个人的印象。**
- 上下文：`build_context` 的 `news` 字段会进提示词，明确标成「你今天读到的（不是你的经历）」；日记提示词同样——她可以有自己的看法，但不能假装亲历。
- `seed news <生命包> [--day N]` 读回某天她读到的内容。

## 5. 记忆条目

```json
{
  "id": "m_0002_1",
  "day": 2,
  "at": "2026-10-31T09:00:00.000Z",
  "kind": "conversation",
  "text": "主人问我今天怎么样。我说光有点淡。",
  "importance": 0.55,
  "tags": ["主人"],
  "source": "life/0002-2026-10-31.md",
  "runner": "stub-v1"
}
```

- `kind`：`conversation` / `diary` / `thought` / `feeling` / `correction` / `forget` / `perception` / `hearsay`（1.10）
- **条目不可改。** 修正 = 追加一条 `correction`；「我忘了」= 追加一条 `forget`。
- `runner` 记录是哪一版认知循环写的——`stub-v1`、`hatch`，或某个真实模型。
- 每轮普通提炼默认最多 8 条（可在 `mind/memory.json` 调）；普通单条 text 最多 200 字，关联更正最多 1000 字。

## 6. 写入规则

- 脑输出结构化 JSON，可包含 `reply`、`memory_writes`、`development`、`corrections`、`actions`。旧 `self_edits` 忽略。对话最多可先进行两次 `memory_search`，因此最多三次模型请求。
- **脑只提案，运行器落笔。** 运行器检查结构、可用引用和操作范围；引用存在不等于事实独立核实，也不能保证模型绝不误解。
- 写入门槛：`importance ≥ 0.3`；每轮最多 `daily_max` 条（兼容旧键，默认 8）；单条过长截断。更正独立于此配额。
- 记忆卫生（`mind/memory.json`，默认 `{"strict": true, "daily_max": 8}`）：
  - `strict=true`：同一天内去重（忽略空白/标点）、丢弃短于 4 字、丢弃「好 / 嗯 / 知道了」这类空话；
  - 隔天又想起同一件事是自然的，不跨天去重；
  - 弱模型（本地 Ollama 等）写的记忆更容易乱，严格模式就是为它们准备的。
- 提炼目标（仍需模型遵守和输出评估，不是事实正确性证明）：
  1. **只减不加**——只能用原文里出现过的词，不许补新细节。
  2. **保留锚点**——人名、日期、承诺、「不」必须留下。
  3. **区分事实与感受**——感受可保留，但不得补造原文没有的情绪。

## 7. 读取（检索公式）

```
score = 3 × relevance + 0.5 × importance + 0.2 × recency

recency   = 0.5 ^ (距今天数 / 30)        // 30 天减半
importance ∈ [0, 1]                      // 写入时打分
relevance = 命中的查询词组数 / 查询词组数  // 无 query 时为 0
```

- 取 top-k（默认 8）进窗口。
- 出生身份和当前消息优先；旧摘要、近日日记、相关记忆按来源规则和容量选取，不能绕过更正或放下规则。
- Python 本地文字检索使用汉字、假名、韩文的二/三字片段及 Unicode 单词；查询和索引使用 NFKC 与大小写归一化，保留原文。相邻拉丁字母与 CJK 分段，避免混合文字漏查；词面匹配不代表同义、翻译或事实判断。索引包含原始档案，文字缓存 v6 在下次使用时从原始文件重建旧版索引，并保留已知模板来源。结果先经过可见性/日期过滤，再按相关性等排序；索引故障使用同一分词规则回查原档。另有明确启用的可选语义通道，见 [混合检索](../docs/23-hybrid-memory-retrieval.md)；本轮不更改其配置或请求规则。

## 8. 遗忘与记错

- 原记录不覆盖；更正、放下通过追加关联事件改变后续读取。
- 间隔重复、月度整合与长期总结仍属后续设计，不能把自动生成摘要等同于可靠成长。
- **记错**：允许模糊（「那天好像下了雨」），不允许无中生有；且必须能追溯到 `source`。
- 她可以知道自己忘过：追加一条 `kind: forget`。

### 8.1 忘记（1.5，只追加不删除）

主人可以让她忘掉某条记忆。**忘记不是删除**——旧行永远留在 `mind/memories.jsonl` 里，只是追加一条"墓碑"：

```json
{"id": "m_0003_2", "day": 4, "kind": "forget",
 "text": "已放下一条记忆；正文仅保留在历史档案中。", "tags": ["忘记"],
 "importance": 0.0, "source": "forget", "runner": "forget-v1",
 "at": "2026-10-31T20:00:00+08:00", "forgets": "m_0002_1", "reason": "不重要了"}
```

规则：

- 墓碑的 `kind = "forget"`，`forgets` 指向被忘记的记忆 id；
- **召回、上下文注入、默认记忆列表排除放下记录及墓碑**；读取也屏蔽已知依赖和关联原始事件。旧日级来源采用保守屏蔽，存在少召回无关内容的代价；
- 墓碑仅在用户查看历史时显示，不复制旧正文，也不回送模型；
- `life/` 原文**不删不改**——日记里那天发生过的事仍然在，只是她不再主动想起；
- 重复忘记同一条 id 视为错误。

参考实现：`list_memories()`（带 `forgotten` 字段）、`forgotten_ids()`、`visible_memories()`、`forget_memory()`。

## 9. 上下文预算（参考，中文约 6k 字）

| 部分 | 预算 |
|---|---|
| 世界 + 自我（不变前缀，可走 prefix cache） | 2.3k 字 |
| 检索到的记忆（top 5–10） | 0.8k 字 |
| 今天的原文 | 2k 字 |
| 输出 | 1k 字 |

## 10. 不做什么

- 不用 token 级压缩（LLMLingua 类）处理她的语言——会伤她的声音。
- 不让脑直接改写 `life/`。
- 不让压缩器发明原文里没有的人、事、细节。
- 不把她的全部记忆塞进窗口——她本来就记不全。
- 不把「读到的」写进别人的档案：见闻不进 `friends/`，也不冒充她亲历。
- 不自己去互联网抓东西：见闻只能由主人/载体按白名单交进来。

## 11. 参考实现（v1.0，Python）

`tools/seed/seedbank/cognition.py`，零依赖标准库：

| 函数 | 作用 |
|---|---|
| `open_day(pack)` | 找到当前还开着的一天（最后一天文件里没有 `## 今天`），否则新一天 |
| `append_transcript(pack, day, entries)` | 把对话追加到当天的 `## 对话` 段（自动用她的名字作为落款） |
| `build_context(pack, day, message)` | 组装一次对话需要的全部上下文：出生证、物种、心情、特征、身份、世界、自我、信念、召回的记忆、当天原文、最近几天 |
| `normalize_memory_writes()` | 校验脑的记忆提案，落成记忆条目 |
| `chat_turn(pack, message, brain)` | 一次对话：调脑 → 写对话 → 写记忆 → 写自身修正 |
| `run_days(pack, days, brain)` | 推进 N 天：今天有对话就收尾，否则空转/独处，写日记与心情 |
| `recall(pack, query, k)` | 按检索公式取回记忆（已忘记的不参与） |
| `read_sense_lines(pack, day)` | 读当天 `## 感知` 段，放进脑的上下文 |
| `sense_media(pack, image=, sound=, note=)` | 让她看一张图 / 听一段声音 / 听主人说话，写 `## 感知` 与 `perception` 记忆（见 [senses.md](senses.md)） |
| `list_memories(pack)` | 全部记忆（带 `forgotten` 标记，记忆页用） |
| `visible_memories(pack)` | 还能被想起来的记忆（召回/上下文用；墓碑保留，被忘记的原条目排除） |
| `forgotten_ids(pack)` | 被墓碑指向的记忆 id 集合 |
| `forget_memory(pack, id)` | 忘记一条记忆：追加墓碑，原行不动 |

```bash
python tools/seed/seed.py chat ~/fish/小蓝.life --once "你好呀"
python tools/seed/seed.py sense ~/fish/小蓝.life --image 窗外的光.png --note 给你看
python tools/seed/seed.py day ~/fish/小蓝.life --days 3
python tools/seed/seed.py recall ~/fish/小蓝.life --query 光
python tools/seed/seed.py memories ~/fish/小蓝.life
python tools/seed/seed.py forget ~/fish/小蓝.life m_0002_1 --reason 不重要了
```

- `chat` 和 `day` 默认使用 `mind/brain.json` 指定的脑；`--brain` 可临时覆盖。
- stub 脑不联网、确定性地生成日记与回应：先验证跨天连续性与文件结构，接真脑时只替换生成部分。
- 真脑失败（网络/额度）会退回 stub 并继续活着，终端给出提示；`runner` 字段记录实际是谁写的。
