## 1. 一句话

**持续运行跨过午夜时，结束前一页并创建当天日页；离线后恢复实际日期。**

没有「事件驱动」模式或「真实时间」开关。时钟不自动决定衰老、成熟或死亡。

没有日页的期间不补写，也不推断睡眠或没有经历。已存在的日期不重写。

## 2. 配置文件

位置：`<生命包>/mind/clock.json`（可选；不存在 = 全部用默认值）

```json
{
  "format": "seedbank/clock@1",
  "last_seen_date": null,
  "updated_at": null
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `format` | 字符串 | 固定 `seedbank/clock@1` |
| `last_seen_date` | `YYYY-MM-DD` 或 null | 上一次运行器检查时钟的本地日期 |
| `updated_at` | ISO 8601 | 最后一次写文件的时间（自动写） |

规则：

- 老生命包里可能带着 `mode` 字段（1.7.0 的遗留）：**忽略它**，不报错，也不再写回。
- `last_seen_date` 必须是合法的本地日期（`2026-13-01` 这种直接拒绝）。
- 写文件必须原子写；只允许改 `last_seen_date` / `updated_at`。

## 3. 一天怎么开、怎么闭

她的「天」写在 `life/NNNN-YYYY-MM-DD.md`：

- **开**：文件存在，尚未写 `## 今天` 或 `## 记录暂停`。
- **闭**：有日记，或有暂停说明及对应的运行器日期转换记录。
- 同一天里可以聊天、发图、看东西；闭合之后，这一天就定稿了。

时钟只做三种事：

| 情况 | 行为 |
|---|---|
| 首次检查，或旧版本留下落后于今天的日页 | 保留原日期；必要时追加暂停说明，仅新建今天的日页 |
| 跨了 1 个凌晨，末页日期与上次检查一致且还开着 | 写该页日记，闭合后立即创建今天的日页 |
| 跨了 1 个凌晨，末页已闭合且日期正常 | 新建今天的日页 |
| 跨了 N>1 个凌晨 | 记录检查空档；保留旧页，仅新建今天的日页，不生成中间日记 |
| 今天已有日页 | 不重复创建；更新检查日期 |
| 当前日期早于上次检查，或末页晚于今天 | 不改写历史或倒退检查日期，返回原因 |

日历空档只能说明缺少记录，无法证明实际活动、睡眠、死亡或关系变化。逻辑页号仍连续，日期可跨过明确记录的空档。例如第 2 页是 11 月 2 日、第 3 页是 11 月 7 日，中间不生成四篇虚构日记。

连续运行时，一天就是真实的 24 小时：凌晨之后第一次看钟，闭合前一天并开出新的一天。

## 4. 什么时候看钟

| 入口 | 看钟时机 |
|---|---|
| 独立窗口 `seed window` | 启动约 1 秒后看一次；之后每 60 秒一次 |
| 网页窗口 `seed serve` | 启动时一次；后台每 60 秒一次；每次对话/发图前 |
| 载体桥 `seed bridge` | 每次 `message` / `image` / `sound` 前 |
| 终端 `seed chat` | 每次对话前 |
| `seed tick` | 手动（脚本/测试用） |

看钟是**幂等**的：同一秒里被多个入口调用，也只会推进一次。任何入口的时钟失败都不该挡住说话（错误被吞掉，只影响时间）。跨凌晨写日记时如果脑不可用（缺 key / 网络 / 配置错），退回离线 stub 写日记并照常翻页——时间不能因为脑坏了就停住；stub 写的那一天会在 `journal/` 里留下 runner 记录。

## 5. 时间空档记录

`journal/loop.jsonl` 追加一行：

```json
{"mode": "clock_gap", "at": "2026-11-03T09:00:00+08:00", "from_date": "2026-10-31", "to_date": "2026-11-03", "unobservedDays": 2, "activity": "unknown"}
```

这是两次检查之间未观察到的日数，不保证期间没有其他运行器活动。`tick` 响应保留 `sleptDays` 旧字段作为 `unobservedDays` 的兼容别名，不再将它解释为睡眠。旧 `mode=sleep` 日志保留，不重写。

日页跨日空档或暂停时，新增 `runtime_gap` 经历，保存 from_day/from_date/to_day/to_date、missing_dates、paused_previous、last_seen_date、activity=unknown。来源指向恢复日页。Python `check` 只允许有这条前向、相邻逻辑页号、准确日期和来源对应记录的日期间隔；缺失解释、倒序日期和跳号仍拒绝。`## 记录暂停` 不代替日记正文，不会调用模型补写。

## 6. 命令行

```bash
# 看她现在的时间
seed clock <生命包>

# 按真实日期推进一步（用于脚本/测试；正常由窗口自己调用）
seed tick <生命包> [--now 2026-11-01T00:05:00+08:00] [--brain stub]
```

`seed clock` 没有 `--mode`，也没有别的开关。输出是一句人话：

```
她的时间：按真实的一天走（每过一个凌晨她过完一天；上次看到她：2026-10-30）
她的时间不需要设置：每过一个凌晨，她就过完一天。
恢复实际日期，不补写空档；期间经历未知。
```

`seed tick` 返回翻页或恢复原因；日页数量与日历间隔分别记录。

## 7. 窗口与设置页

- 设置页「时间」卡片只解释，不提供开关：`她的时间不需要设置：一天就是真实的一天。`
- 窗口关掉 → 时间停（下一次打开时由 `last_seen_date` 决定跨过了几个凌晨）。

## 8. 与「记忆条数」的关系

两件容易混淆的事：

| 问题 | 答案 |
|---|---|
| 每轮最多提炼几条记忆？ | 默认 **8 条/轮**（兼容键 `daily_max`，可调 1–50），不限制当天后续交流继续形成记忆 |
| 天是按 24 小时走吗？ | 是。每过一个凌晨过完一天，没有别的模式 |

两个数字互不影响：一天的记忆上限，和一天有多长，是两件事。

## 9. 不做什么

- 不补写没运行的日子。
- 不改历史文件的日期。
- 不联网校时（用本机时间；时钟往回走就当作「不动」）。
- 不做定时任务/后台常驻服务：窗口关着，她就停。

## 10. 兼容性

- 出生页的初始“今天”叙述不表示真实出生当天已经结束。时钟已记录出生日期时，首日交互留在出生页；首次午夜追加独立“当日日记”，保留出生叙述，再开次日页。日记摘要优先取当日日记。未启用时钟的显式逻辑日模拟仍沿用原有日页行为；不重写旧日期。

- 老生命包没有 `mind/clock.json` → 第一次检查同时对齐实际日期，保留旧页；没有出生页时拒绝补造。
- 老包里带 `mode` 字段 → 忽略，不迁移、不报错。
- Python `seed check` 识别明确的日期空档；旧运行器可能拒绝这些日页，不能据此删除空档记录。
- 原日期、出生档案和旧正文保留。新暂停说明、运行器经历和当天日页进入现有事务。
