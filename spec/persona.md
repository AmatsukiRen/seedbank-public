# 固定样本连续性评估

> 2026-11-02 扩展（未测试）：来源指纹新增第 11 项 `mind/life_story.jsonl`，解释修改使旧样本过期。旧 6–10 项样本保留为历史，需明确重建；不自动请求模型。样本仍检查有限资料的理解，不证明个体同一或完整一生。

版本 2.0，2026-11-02。实现与用例已编写，尚未执行测试。保留 `persona` 命令名，撤销旧版“文字相似度证明还是同一个人”的含义。

## 测量范围

分开记录两个问题：样本来源文件是否变化，以及当前模型能否读取固定资料并正确引用。它不证明人格同一性、意识、自然对话的召回率或现实事实为真。

每次最多 8 个维度，各取有限记录：

| 维度 | 样本与判据 |
|---|---|
| identity | 出生记录中的名字与种子编号；不能从界面形象推导鲸鱼身体或童年 |
| memory | 一条当前可回忆记忆的原文，最长 1200 UTF-8 字节 |
| revision | 一组可见修订关系；区分原来有误与后来变化，未知变化日期保持未知 |
| source | 最近可用的梦、创作、转述各一条；区分想象与转述，不能宣称亲历 |
| promises | 每种已出现状态的最新一条承诺，区分 pending / kept / broken |
| reminders | 每种已出现状态的最新一条提醒，区分 pending / said / missed |
| goals | 当前有有效依据的目标，每种已出现状态取一条 |
| unknown | 对样本未提供的出生前访客姓名承认未知，不推断整个生命档案一定没有记录 |

没有合格记录的维度标记 `no_eligible_record`，不是通过。事项只发送编号和状态：旧事项缺少可靠的遗忘依赖，不能把可能已放下的正文再次送出。相应评估只能说明状态读取，不能证明理解了承诺内容或会履行它。修订也只检查结构关系，不能证明语义纠错质量。

## 样本与协议

`mind/persona.json` 格式为 `seedbank/persona@2`，包含唯一编号、创建时间、提示词及版本、来源摘要、题目、覆盖范围、运行器计算的预期答案和基线模型输出。样本及基线评估分别保存 SHA-256，用于发现意外改动，不是对抗恶意重算摘要的签名。

来源集合固定为 `birth.json`、`mind/memories.jsonl`、`mind/experiences.jsonl`、`mind/development.jsonl`、`mind/bonds.json`、`mind/hands.json`、`mind/facts.jsonl`、`mind/learning.jsonl`、`mind/relationships.jsonl`、`mind/disclosure.jsonl`。旧六至九文件样本仅作为历史，需重新建立当前样本。按块读取摘要，不枚举整个人生文件夹。缺失文件也进入摘要状态。这里只检查样本依赖文件，不应称为全包完整性验证。

两个模型收到相同提示词和相同题目资料。`expected`、旧模型输出和评估结果不会发送给被评估模型。回答结构：

```json
{"answers":[{"id":"identity","status":"known","value":{"name":"初","seed_id":"open"},"evidence":["birth.json"]}]}
```

每题核对 `status`、`value`、`evidence`。引用字符串需要一致，编号列表不考虑顺序。缺失、重复、额外题号不能整体符合。没有使用文字相似度或另一个模型裁判。网络/解析失败、stub、适配器不支持、运行器来源不充分、容量不足都不算通过。

输入按 UTF-8 字节代理预算检查，预留 512 字节，不是精确 token 计数。超限时整份样本不发送，不悄悄删题。正式适配器直接调用既有传输，不启动对话检索、记忆提炼、日循环或失败后的 stub 回退。模型名称来自配置/适配器默认值，不是厂商认证的不可变权重版本。

## 运行与保存

1. `persona capture`：在当前模型上创建样本并记录表现。stub 只保存样本，能力评估为空。已有基线原字节保存到 `mind/continuity/archive/<唯一编号>.json`，与新基线替换在同一个本地事务内完成。
2. 更改并保存模型配置；这不会修改出生身份或样本。
3. `persona check`：先核对来源。任何依赖文件变化都标记 `stale_sample`，不创建模型、不重发旧内容。需要重新捕获后再比较。普通生活更新也可能使样本失效，这是目前的保守策略。
4. 模型请求后再次检查来源，以检测不遵守应用锁的外部改动。期间变化的结果不用于比较。
5. 每次检查存为 `mind/continuity/reports/<唯一编号>.json`，同时更新 `latest.json`。报告保存来源状态、实际运行器、配置模型标签、请求耗时、逐项结果以及相对基线的新增差异/改善。
6. 只有基线和新模型都完成评估时，才生成两者比较。基线失败项不会成为新模型的正确答案。

应用持有生命包单写者锁，写结果用本地事务。远端请求与费用不可回滚；中断后再次执行可能重复收费。报告不写入记忆、成长、日记或自我叙述，不进入检索索引。归档与备份仍保留原文，“放下”不是物理删除。

旧 `persona@1` 可被识别，但不能继续运行旧问题或输出人格通过。用户重新捕获时旧文件归档。数值 `--threshold` 已移除其意义，传入时明确报错，不静默忽略。

## 用户入口与退出码

Qt：设置 → 对话 → 换模型前后的档案理解。按钮明确告知调用已保存模型及可能收费；有未保存对话设置时不执行。打开面板或刷新只读摘要，不调用模型。JSON 报告可从评估文件夹查看。换模型不自动启动评估。

```powershell
python tools/seed/seed.py persona capture "D:\体验\初.life"
# 用户更改并保存模型配置
python tools/seed/seed.py persona check "D:\体验\初.life"
python tools/seed/seed.py persona status "D:\体验\初.life"
```

`capture` 返回 0 表示样本保存成功，不能解释成模型通过。`check`：0 表示本次有覆盖样本全部符合；1 表示样本差异或命令错误；2 表示未评估。桥 `ok=true` 表示操作完成，评估是否执行以 `persona.status` 和 `persona.passed` 为准；未评估时 `passed=null`。

```json
{"op":"persona","action":"capture"}
{"op":"persona","action":"check"}
{"op":"persona","action":"status"}
```

## 尚未证明的能力

该流程是受控资料读取检查，不是端到端回忆评测。广泛的情境改写、长期检索、人物关系、价值判断、行动决策与实际履约，需要另建来源明确的场景和持续观察。有限样本全部符合也不能推导整个个体没有变化。旧版字符相似度通过的历史结果不作为新版有效证据。
