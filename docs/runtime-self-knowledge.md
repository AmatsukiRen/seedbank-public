# 自我介绍与当前渠道状态

出生是个人经历开始累积的时间，不意味着个体不知道自己的名字、出生记录或已经接入的交流能力。外观仍然只是展示载体，不由 Live2D 推定种族、身体、童年或既往生活。

本次修复前，桌面程序知道 QQ 接收服务是否启动，但对话上下文没有提供这些信息。因此模型可能反复回答“看不到设置，也没有连接依据”。现在每轮上下文都会附带一份由运行器提供的临时状态，经过同一预算裁剪后送到模型；提示版本为 `seedbank-memory-v43`。

## 提供什么

- 主人范围内沿用档案中的姓名、出生时间、当前日页；不重新写出生身份。
- 当前输入来自桌面、QQ 或其他已接入的内置渠道。没有运行器依据时保持未知，不从用户话语、请求编号或旧回复推测。
- 本进程的 QQ 接收服务、其他渠道工作进程是否正在运行，以及本轮连接启动以来收到、发送成功、处理失败的数量。
- QQ 仅对允许的私聊及白名单群内的 @消息回复。回复由载体转发，不意味着模型可以自行进群、读取聊天历史或任意主动发消息。

“接收服务正在运行”不等于外部账号已登录；收到一条消息只证明这一条到达；发送成功回执也不保证未来连接持续正常。保存设置不会自动接通。停止或重开程序后重新读取运行状态，不把旧计数恢复成在线证明。

## 隐私与记忆

这份状态通过程序内部作用域传递，不接受聊天文本或 JSON 桥字段覆盖。仅白名单状态和计数进入模型上下文，不含密钥、QQ 号、群号、接口地址或本机配置路径。群聊只获得当前渠道及本条来信的事实，不获得私人身份和其他渠道的流量。

状态本身不写入出生、记忆或成长档案；正常对话仍按原有规则记录。后续询问连接时，以新状态为准，不用旧回答代替当前证据。设置保存、切换模型、后台活动和独立进程内 QQ 桥均沿用同一机制；旧的外部子进程桥没有可验证的运行器状态时仍报告未知。

## 验收

16 项新增用例覆盖新生自我介绍、实际模型请求中的状态、QQ 来信和回执、停用/重开、其他渠道、群聊隐私、伪造字段、跨包和异常退出隔离、模型切换、后台上下文及多渠道同时运行时的长对话保留。均使用临时人工包、假模型和假发送器。

入口为 `packaging/run_offline.ps1 -Suite integrations`；相关记忆、遗忘、来源、生命周期和预算回归为 `-Suite core`。具体版本、执行结果和限制见[验收记录](acceptance.md)。这验证的是运行器与模型请求通路，不代替真实服务的连通性或模型回答质量验收。
