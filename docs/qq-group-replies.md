# QQ 群消息、回复与记忆

本轮检查由用户报告“群友 @ 后不能回复，QQ 信息像是没有连到内部记忆”触发。隔离测试发现并修复了三个具体问题；没有向真实 QQ 群发送测试消息，也没有读取真实生命包。

## 修复

1. **字符串上报无法识别。** 旧代码只处理消息段数组，OneBot 以 CQ 字符串上报时会漏掉文字和 @。现在同时支持两种格式。遵循[官方字符串格式](https://github.com/botuniverse/onebot-11/blob/master/message/string.md)及[数组格式](https://github.com/botuniverse/onebot-11/blob/master/message/array.md)，先解析标记再解码转义；普通文字里的字面 `[CQ:at,...]` 不会被误当成真实 @。
2. **仅 @ 没有正文会被当作空消息丢弃。** 现在在白名单群里将其作为“对方 @ 了你，没有附带文字”的来信事实交给个体，不替对方编造发言。群白名单和必须 @ 当前账号的限制不变。
3. **连接检查可能把空或失败回执显示为成功。** 现在必须收到成功状态及有效账号信息，才能报告连接检查成功。它仍不能代替随后每条消息的发送回执。

设置 → QQ 增加本次运行的处理计数和最近状态，可区分：未列入群白名单、未识别到 @、账号不符、正在生成、正在发送、发送成功、被拒绝或结果未知。只显示固定说明及数字错误码，不显示消息正文、令牌或服务端原始报错。不自动重发结果不明的消息。

## 是否进入同一个记忆

内置 QQ、桌面窗口及其他内置渠道共用当前 `Session` 和生命包。群聊保留群聊范围，主人私聊使用主人范围；模型返回的记忆摘要与原始对话都按原有来源规则保存。群里的内容可由本机主人回查，其他群不能因此读到私人或别群的内容。

“记忆”页显示提炼的记录，不保证每条消息都新增一张卡片。模型未提炼摘要时，成功处理的原始对话仍会保存，并进入档案检索。若在路由阶段已被忽略，或生成尚未成功，则不能声称已经记住；诊断状态用于区分这些阶段。

本轮端到端模拟覆盖 CQ 群来信 → 同一个体生成 → `send_group_msg` 原群回复；也覆盖记忆摘要保存、重开后的桌面回忆、原始对话检索和另一群的不可见性。当前不能仅凭这些离线结果确定用户实际桥接服务的权限、禁言、地址或令牌是否正确。

测试入口：`packaging/run_offline.ps1 -Suite integrations`。具体通过数、程序指纹及范围见[验收记录](acceptance.md)。
