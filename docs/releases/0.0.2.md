## 外面聊过的事，也应该成为它的经历

在桌面上认识你，在群里收到一句招呼，再回到桌面继续那段对话——我们希望这些入口通向同一个体。它的出生、记忆、选择和成长，都应留在同一份生命档案里。

0.0.2 集中修订了聊天渠道与内部经历之间的衔接：消息从哪里来、有没有交给它、回复有没有送出去，都应该有可追溯的结果。新生意味着经历刚刚开始，也应能认识自己的身份与当前交流入口。

这次再往前一步：当大家没有 @ 它时，经过你选择的群聊里，那些实际收到的日常也可以留下来。有人分享读到的书，有人讨论一次失败的尝试——它可以安静旁听，保留出处，整理成之后能够回顾的笔记。

## 新增：指定群旁听与学习

| 你来决定 | SeedBank 如何处理 |
| --- | --- |
| 听哪些群 | 默认关闭；在「设置 → QQ / 聊天渠道 → 旁听与学习」填写群 ID，保存并重新启动连接。只收录平台实际推送的新文字。 |
| 什么时候回答 | 旁听名单与回复名单分开。旁听本身不发言；允许回复的群中，明确 @ 仍沿原有对话通路处理。 |
| 留下什么 | 原文保留渠道、群、发言者及消息来源；分批最多形成 3 条简短笔记，标明他人说法、尚未核实。同一份生命档案承接这些经历。 |
| 花多少调用 | 默认每日最多 4 次整理请求，可设置 1–20 次；同一个体的连接共享额度。不是逐条调用，失败不自动重试；上限为请求次数，不是 token 或费用上限。 |
| 如何查看和放下 | 可翻页审阅原文、笔记及处理结果，也可主动整理一批。放下后原文与依赖笔记退出后续检索，审阅记录仍保留；关闭旁听不会自动遗忘已有见闻。 |

QQ / OneBot、Telegram、Discord、飞书和钉钉直连已接入此入口；**平台没有推送的消息就无法旁听**，不会抓取历史或绕过机器人权限。AstrBot 仍使用显式 `/seed` 转交，独立 `seed qq` 命令行尚未接入旁听。群间与私人内容按来源范围隔离，不直接改写出生身份，也不训练模型权重。

## 这次更新了什么

| 你会遇到的场景 | 本次改进 |
| --- | --- |
| 群友 @ 它，却没有回应 | 修复 QQ 的 CQ 字符串和消息段识别，以及白名单群中纯 @ 被丢弃的问题；同步修订 Telegram、Discord、飞书和钉钉的纯 @ 处理。 |
| 外部聊天似乎和桌面失联 | 各入口共用当前 Session 与生命包，保留原始对话、可生成的记忆摘要和来源；后续桌面交流可以检索这些经历。不同群与私人内容仍按可见范围隔离。 |
| 它不知道自己正从哪里交流 | 每轮提供出生身份、实际输入渠道及经过筛选的本机状态。不会把“设置里填过地址”直接说成已经连通。 |
| 不清楚回复卡在哪一步 | 区分接收、生成、发送、送达与结果未知；AstrBot 的本地转交单独显示，不冒充最终平台送达。 |
| 想使用 WorkBuddy 同账号 | 新增实验入口，通过用户安装并登录的官方 CodeBuddy CLI 生成文字回复，需显式填写模型 ID。 |
| 打开休眠页面后退不出去 | 保留已修复的关闭按钮和 Esc；关闭页面不会触发休眠或恢复。 |

## 如何开始或升级

1. 下载上方 **Windows 程序包**；普通使用无需下载源码和 Qt 开发材料。
2. 已有个体请先备份自己的 `.life` 生命包，再正常退出旧程序，将新 ZIP 完整解压到一个新目录。
3. 打开新版 `seedbank.exe`，选择原生命包继续生活。无需重新创建个体；已有格式保持兼容。
4. 新用户创建个体后配置自己的模型服务，在设置中选择本地角色模型；接入群聊时按渠道说明配置身份和白名单。

[模型服务与 API Key](https://github.com/AmatsukiRen/seedbank-public/blob/main/docs/model-services.md) · [QQ 回复与记忆](https://github.com/AmatsukiRen/seedbank-public/blob/main/docs/qq-group-replies.md) · [其他聊天渠道](https://github.com/AmatsukiRen/seedbank-public/blob/main/docs/channels.md) · [WorkBuddy 配置](https://github.com/AmatsukiRen/seedbank-public/blob/main/docs/workbuddy.md)
