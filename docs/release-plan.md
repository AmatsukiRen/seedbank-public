用户已确定首个公开版本为 **0.0.1**，对应 Git 标签 **v0.0.1**。这是新产品发行线的起点；研发阶段的旧编号与历史记录继续保留。

机器可读目标保存在根目录 `release-plan.json`；它只记录计划，不是安装包已发布的标记。

## 版本规则

迁入应用后，让包元信息、CLI、窗口显示、启动和打包说明引用同一应用版本来源。发布时为 0.0.1；需要分发试用候选时，可另行使用 0.0.1-alpha.1 等预发布编号，不能让多个不同候选都冒充最终发行包。

生命包、记忆索引、协议及提示词的格式版本不随应用版本重置。编号从 0.0.1 开始不代表可以清空数据或忽略兼容性。

0.0.1 之后，普通修复从 0.0.2 继续；更大的功能里程碑另定版本。旧研发包不改名为 0.0.1，也不补写新的历史测试结果。

## 到首发的顺序

1. 完成页面、README、品牌与首次使用流程设计。
2. 按明确清单迁入当前应用源码，整理版本和通用路径。
3. 补充用户文档、素材说明、人工包实机截图和发行说明。
4. 由用户运行候选版本的离线、启动、界面与备份恢复验收，保留对应版本的结果。
5. 整理可公开文件与实际证据，再按用户明确指令将仓库公开。
6. 在验收对应的提交上建立 v0.0.1，发布标为预发布的 Alpha Release，附安装包、摘要和已知限制。

第 5 步公开源码与第 6 步发布安装包可以分开进行。本次只是确定版本与提交草稿，不执行这两步。
