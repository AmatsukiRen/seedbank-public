# 首次发行计划：0.0.1

SeedBank 在私有仓库内完成整理，再开放同一个产品仓库，首个安装包版本为 **0.0.1**，计划标签 **v0.0.1**。公开源码与发布安装包可以分开进行；无需维持一个长期对外的“设计稿项目”。

## 当前进度

| 项目 | 状态 |
| --- | --- |
| 三语 README、完整故事、角色与 Live2D 署名 | 已整理 |
| 开发接入指南、贡献方向、离线参考客户端 | 已整理；示例未运行 |
| 应用核心与打包源码迁入 | 待完成，当前实现仍在原研发库 |
| 当前版本的五页实机图片 | 已准备用户采集入口，待采集与查看 |
| 0.0.1 候选的安装、界面与备份恢复验收 | 待用户执行 |
| 素材的公开使用范围与通用路径整理 | 待完成 |
| 仓库公开、v0.0.1 标签与 Release | 尚未执行，仓库目前 PRIVATE |

## 接下来的顺序

1. 按明确清单迁入当前核心、UI、测试材料和打包脚本，保留 MIT 贡献归属。
2. 统一 0.0.1 版本来源，整理通用的模型导入、配置与首次使用说明。
3. 补上候选的五页图片、用户文档和已知限制，由用户执行相关验收。
4. 准备完成后，按用户明确指令将这个产品仓库设为公开；在对应提交上发布 v0.0.1 Alpha。

README 按正式产品的介绍方式维护，私有状态属于筹备过程。删除首页的“设计稿”提示不等于已经发布，也不改变代码迁入与验收的实际进度。

## 版本规则

应用、CLI、窗口与打包使用同一版本来源。生命包、索引、协议与提示词有独立格式版本，不随首发编号重置。旧研发包不重新标为 0.0.1；必要时用 0.0.1-alpha.1 等区分候选。
