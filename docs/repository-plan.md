## 静态审阅中处理的问题

1. 旧包元信息 1.2.0 与运行核心 1.23.0 不一致：统一应用版本为 0.0.1，并让安装元信息、CLI、Qt 窗口和 Windows 文件版本读取同一来源。生命包和协议格式版本不变。
2. 默认 Live2D 指向维护者 D 盘：改为空选择，有明确提示和入口；已有用户显式选择的模型路径仍保留，清除选择不删除模型文件。
3. Python 包遗漏语言资源、README 不存在：补齐资源配置和说明。依赖要求按 Live2D 运行库调整为 Python 3.11+。
4. 原文档仍要求回到研发库找源码：更新三语首页、安装、扩展和贡献指南。

## 交付与边界

本库仍为 PRIVATE；Windows 程序放入 v0.0.1 的私有发行草稿，不写入 Git 历史。最初迁入时没有启动候选或运行测试；之后的验收与各次打包对应关系以 [acceptance.md](acceptance.md) 为准，不能将最初状态当作当前测试结果。

公开前需用户验收当前候选，并确认品牌图片公开使用范围及适用的运行库发行条件。已有结果与待执行项分别见 [acceptance.md](acceptance.md) 和 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。

## 源码公开与 Windows 发行分别推进

Live2D 功能继续保留。自有集成代码的公开准备与包含 SDK 的程序发行分别记录，不能把存在 Live2D 接口理解为禁止公开自身源码，也不能把源码 MIT 理解为给 Core、角色和截图重新授权。

| 交付 | 实际包含 | 当前仍须处理 |
| --- | --- | --- |
| Git 仓库 / 应用源码 ZIP | 自有 Python/QML、协议、插件示例、构建方法、文字种子、已有头像与截图；不附 Qt/Cubism 二进制 | 素材许可与独立署名范围，公开前用户确认；保留种子的 CC BY-SA 条款 |
| Windows ZIP | 应用、Python、Qt/PySide、live2d-py/Cubism 等运行库及文档 | SDK 发行安排、Qt 对应源码/通知/重建条件、新包的用户测试 |
| 第三方对应源码 | 与发行库匹配的上游源码、修改及构建信息 | 应单独取得和提供；应用源码 ZIP 不代替第三方对应源码 |

当前仓库及历史已经含有品牌衍生图和截图，因此不能仅将 README 图片撤下就宣称整个历史不含第三方素材。本轮不移除认可的头像、不重写历史，也不擅自公开。

生产入口现在为每个 exe 记录 `runtime-build.json`：源码提交、工作区状态、字节数和 SHA256。组包只接受与该记录一致的干净提交，并生成同一提交的 Source ZIP，避免新源码配旧 exe。没有验收报告时，包内明确记为未测试；不会复用其他 exe 的通过记录。
